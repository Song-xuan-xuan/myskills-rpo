### 吞吐能力

平台整体吞吐能力的理论上限由式 {{eq:cap}} 决定：

::: {#eq:cap}
$$
Q = \frac{N \cdot B}{T_{p}} \times \eta
$$
:::

其中 $N$ 为并行节点数，$B$ 为单节点带宽，$T_{p}$ 为单批处理耗时，$\eta$ 为链路有效利用率。

# 技术实现

## 调度改造

调度依赖由脚本内硬编码改为集中配置，核心逻辑如下：

```python
def build_dag(tasks):
    """把任务列表转换成有向无环图，并做环检测"""
    graph = {t.name: set(t.depends_on) for t in tasks}
    order, done = [], set()

    def visit(name, stack):
        if name in done:
            return
        if name in stack:
            raise ValueError(f"依赖成环: {name}")
        for dep in graph[name]:
            visit(dep, stack | {name})
        done.add(name)
        order.append(name)

    for name in graph:
        visit(name, set())
    return order
```

改造后，新增一个任务的配置成本由约 30 分钟降到 5 分钟以内。

## 监控补齐

监控覆盖了四个维度：任务成功率、端到端时延、数据量波动、质量校验通过率。任一维度触发阈值即告警，并自动关联到对应责任组。[^1]

[^1]: 告警规则与值班表由运维组统一维护，季度review 时同步更新。

# 二期计划

二期聚焦三件事：接入层去重、宽表索引重构、指标口径的自动化校验。预计投入 3 人月，2027 年一季度启动。
